# 服务器与局域网采集清单

2026-10-12用户确认当前暂无独立人工标注，先完善离线验证工具。已有59项合成合同验证，现场误认率不据此判定；后续人工标签准备见[标注模板](templates/identity_truth.template.jsonl)及[离线评估输入合同](../docs/open-source-reuse-audit-2026-10-12.md#离线身份错关联评估输入合同)。该JSONL填空模板不是已完成GT，默认 `truth_complete=false`，评估器会拒绝。

复制到新的离线数据目录，一行填写一个P2特征事件：activity/source/observation必须与保存的输入键一致；人工独立确认同人后分配匿名 `truth_person_id`，同一核验组共用 `episode_id`，同组应包含可核对的同人与异人。核对实际登记清单后，已登记人员填写对应target；只有确认未登记才使用null，登记状态未知不能填null。记录可追溯的 `truth_evidence_id`；全部字段和登记状态确认后才设 `truth_complete=true`。不复制算法GID/预测身份或用算法纠错结果生成GT，不要求姓名或身份证。不能确认的资料另存待核验，不从冻结验收集静默删行；全量GT与预测键须完全对应。

该模板只供P2_FEATURE_EVENTS的身份/匿名关联评估。P1整图漏检、质量拒绝和视频丢帧需另收图片/帧级真值，不能从这个JSONL报告算端到端精度。模型/512D、质量及身份阈值保持现状；完整命令与基线冻结规则以输入合同为准。

`episode_id`按独立采集/核验范围提前固定，不能每行单独成组或依据预测结果拆组以避开错并/错分；无同人或异人配对时，报告零计数不能作为相应类别验收。独立匿名person标签不能使用 `auto:`或 `assoc-template:`前缀；填写 `INDEPENDENT_REVIEW`本身不是已经人工核验的证明。

供后续现场取数据使用。先完成普通摄像头的第一批时间轨迹资料，再收集 3D 资料；鹰眼属于另一套上传算法包的 ARM 系统，资料与开发后置，其结果仍需接入统一时空轨迹。本清单不要求现在具备服务器连接，也不要求开发 Java 或前端。

## 第一批：时间轨迹和跨摄像头路线验收

建议先选 **3～5 台实际连通的普通摄像头、5～10 名可核对人员**，采集每人的完整行走过程。包含一条直达路线、一处分叉、一次遮挡／漏拍及一次离开后返回。该规模用于检查功能和输入真实性，不代表全场容量验收。

| 要取的资料 | 必须记录什么 | 在哪里取得 |
| --- | --- | --- |
| 摄像头对应表 | 稳定 camera_id、系统中的原相机 ID、名称、区域、楼层、通道、普通／鹰眼类型、画面宽高；能在平面图标出安装点及观察区域 | 服务器相机配置、相机/NVR 页面、现场平面图 |
| 同人观测和图片 | 原事件／记录 ID、相机、原始时间和单位、来源、图片或录像引用；核对同一人后给匿名 target_id，保留核对依据 attribution_evidence_id | 抓拍库、设备事件、对应录像；目标标签可人工核对，不要求姓名或身份证 |
| 采集时间与时钟证据 | 时间到底来自设备抓拍、视频帧、服务器接收还是处理结束；时区、设备与服务器时间、NTP 状态、查询前后服务器 UTC 时间；采集开始和结束各留一次时钟核对 | 服务器时钟状态、相机时间页面或已可用的设备只读接口、原始事件／录像时间信息 |
| 实际通路图 | 摄像头观察区域之间能走哪些连接，方向、楼层、走廊／楼梯／电梯／入口、分叉、封闭线路、开放时段；每条连接用稳定 edge_id | 场馆平面图加现场走查，不用相机共现代替通路 |
| 通行时间样本 | 对应 edge_id、真实出发和到达时间、测量方法、是否等候／拥堵、路径长度（能测则记） | 现场走查录像或核对后的目标录像 |
| 人工参考轨迹 | 每人实际相机顺序、可核对经过的通道、离开／重入时刻、实际看不到的部分及证据引用 | 与上述观测对应的人工核验记录，独立于算法推断结果 |

记录时间时保留原始值，核对后再生成 UTC 毫秒。只知道接收或处理时间，就标明其来源；`clock_uncertainty_ms` 的依据不足时留空，不能为通过接口填 0。时钟偏移与录像/RTSP 缓冲延迟分别记录。视频 PTS／相对秒数还需要可核对的 UTC 时间锚点；只有文件创建时间不足以证明帧的采集时间。

轨迹核心只接纳有同人归属证据的 `CONFIRMED` 观测，以及 `UTC_CAPTURE` / `UTC`、误差不超配置阈值的时间。新增关联接口可从未归属的人脸特征生成全局 ID 和确认观测；人工标签用于独立验收。可先取得原始资料，回来再整理转换；CSV 模板是采集表，当前服务没有 CSV 导入接口。其他时间源或待定身份仍保留在原始资料中，不冒充合格观测。

通路图中的 `min_travel_ms` 是最短通行时间约束，不是平均通行时间；现场先提供最快通行样本、距离与测量依据，后续共同确定保守下界。`max_travel_ms` 是软评分参考，不是超过它就排除路线。未知的时间下界或方向应明确标为待核实，不能依据单次出现间隔编出唯一通路。短时间离开后重入需有独立证据；另一台摄像头同时拍到不等于已离开原摄像头。

第一批可照着填这五张表：

- [cameras.csv](templates/cameras.csv)：相机 ID、地点和画幅。
- [sightings.csv](templates/sightings.csv)：原始观测、时间及目标归属证据；核对后的字段与 OpenAPI 对应。
- [clock_checks.csv](templates/clock_checks.csv)：时间来源与校时证据。
- [connections.csv](templates/connections.csv)：正式可通行连接及通行时间样本引用。
- [reference_routes.csv](templates/reference_routes.csv)：人工实际路线与重入依据。

同人关联再补一张 [face_observations.csv](templates/face_observations.csv)：记录原始帧 ID、局部 track_id 及会话、检测分数、人脸框最短边、特征文件和模型契约。特征文件保存非零有限 512 维向量，与图片引用一一对应；同时保存 recognition_model_sha256、detector_model_sha256／detector_profile、alignment_version、preprocessing_version、output_version。不能混用不同模型版本的特征。独立人工同人标签 truth_target_id 与算法输出分开，不需要真实姓名／身份证。

阈值标定要同时取同人与不同人的跨相机样本，涵盖正侧脸、不同光照、人脸大小、遮挡、相似脸、同帧多人及局部跟踪换人。另记录相机观察区域重叠对；未核实完整拓扑前保持 topology_is_complete=false。目前代码只实现特征驱动关联，实际错并／拆分率需用这些资料测量，不能用合成向量测试代替。

## 上服务器时取什么

下面路径来自 **2026-09-28 的现场快照和本地归档代码**，上机先核对是否仍然存在、结构是否有变化：

| 历史位置 | 取回内容与用途 |
| --- | --- |
| `/data/facepoc/camera_config.json` | 相机 ID、名称、区域、通道和类型字段；补充现场楼层／平面图位置，统一到 camera_id |
| `/data/facepoc/face_trace.db` 中 `face_trace_record` | 限定所选摄像头与时间段，导出记录 ID、cam、ts、gid、person_id（若存在）、框位置、识别分数、关联图片及文件引用；连同表结构和字段说明带回 |
| `/home/dell/poc_service.py` 及实际服务启动配置 | 核对生成 ts、gid 和原相机编号的代码，记录实际算法/模型版本；以当前运行源文件为准 |
| 服务器和相机时钟状态 | 服务器 UTC／时区／同步状态；各相机时间、时区、NTP 设置及采样时间；保留原始只读返回或截图 |
| Java 现有调用样例、目标字段说明 | 人员实体如何映射 target_id、姓名/业务编号查询返回结构、照片检索使用的模型契约；可用匿名示例，不要求拿回整个 Java 工程 |

抓拍库可用只读连接限定范围导出；如果要取 SQLite 快照，采用一致性备份，包含正在写入的 WAL 状态，避免只拷贝主文件漏掉记录。选定观测的图片须能按原记录 ID 找回，文件名不要承担同人确认逻辑。

历史 PoC 的 `send_track(..., time.time(), ...)` 在推理后赋值，数据库 `ts` 是服务器处理时间；`gid` 是未经人工核验的算法归组。两者均不能直接改名为已确认目标和 UTC 采集时间。历史相机时钟曾存在明显偏移，旧偏移数字不能沿用为此次校正量；本次现场重新采样。

## 在局域网／场馆内取什么

1. 在相机或 NVR 中导出同一时间段的原始录像，写清 camera_id、通道、时间范围和时区，保留帧时间信息及对应事件记录。
2. 给每台参与验收的相机留一张全幅参考图，标出可观察入口／出口及和相邻相机的重叠区域。脸部裁剪用于身份核对，全幅图和录像用于位置、通路与遮挡核对。
3. 沿实际路线走查，把门禁、单向通道、楼梯、电梯、看台通道及不能通行的区域标在平面图上；平行的两条通道分别编号。
4. 对选定人员或已核对录像记录实际行走顺序；有漏拍时保留附近摄像头录像。不能人工确定的路段标为未知，不用算法输出反过来当人工真值。
5. 同步留取设备时钟核对资料。若拿不到真实采集时间，带回原始录像和时间显示证据，注明缺失项，回来再判断能否可靠转换。

## 第二批：真实 3D 路线

| 资料 | 需要的字段／说明 |
| --- | --- |
| 场馆 3D 模型与版本 | 原始模型文件及可导出的 glTF/GLB（若支持）；模型版本、单位、原点、各坐标轴方向、楼层高程；有外部测量坐标时给模型与该坐标系的变换 |
| 摄像头位置和观测映射 | camera_id、安装位置 x/y/z、朝向；全幅参考图和可观察区域／通行入口到模型坐标的对应关系。相机安装点不等于人员观测位置 |
| 可行走导航节点与线 | 节点 ID、x/y/z、楼层；边 ID、起终节点、方向、实际通道折线点、开放限制；映射当前 graph.version + edge_id，覆盖走廊、楼梯、电梯和座位排内通道 |
| 座位表 | 唯一 seat_id、看台/区域、排、座号、x/y/z、楼层、进入该排／座位的导航节点与可行走连接；如已有座位区域几何，一起提供 |
| 指定座位映射 | 匿名 target_id 到指定 seat_id、来源及生效时间；与实际落座证据分开 |

位置、折线和座位统一使用同一坐标系及单位；跨楼层连接保留高度。导航线沿实际通道和座位排通行位置，不能只把两台相机或入口与座位中心直连。该批是后续接入资料，当前 API 尚不接收这些 3D/座位字段。

## 第三批：鹰眼实际落座定位

该批对应另一套 ARM 设备端系统，当前不急；上传算法包的适配与普通摄像头轨迹服务分开实施。后续先取得这些部署资料：

| 资料 | 需要确认的内容 |
| --- | --- |
| 鹰眼设备／平台 | 厂商、型号、固件与算法平台版本，上传算法包的管理入口 |
| ARM 运行环境 | ARM32／ARM64、系统、SDK 支持的工具链与 ABI、可用 CPU／内存及 NPU/GPU 推理运行时 |
| SDK 与上传包合同 | 开发文档、官方示例包、入口函数／进程约定、目录结构、配置及模型格式、依赖、签名／版本要求（平台若有） |
| 输入与输出说明 | 图像／视频输入方式、通道和帧时间来源、局部 track_id 生命周期、定位／事件结构、上传结果的协议和字段 |
| 标定配置方式 | 设备端如何加载相机与座位标定、参数版本，以及视角／预置位改变后的配置切换方式 |

先保留真实样例事件和接口文档，再确定 ARM 端与时空算法的适配。局部 track_id 记录设备／通道／会话来源，核对同人后再映射全局 target_id；坐标与座位结果保留坐标系、模型／标定版本、采集时间和证据。当前 P2 接口不直接接收这些空间／座位字段，后续按实际平台合同扩展，不要求将整套时空服务部署到鹰眼设备。

- **视角和相机参数：** 鹰眼 camera_id、通道、图像尺寸、镜头／全景投影类型；能导出则提供内参、畸变与外参。若有变焦、PTZ 或预置位，记录录像对应状态及状态变化。
- **像素与场馆对应点：** 同一参考画面中的像素 u/v，对应场馆 x/y/z、楼层和实体点说明。点应分布在相关座位区、通道及不同高度表面，另留独立复核点。不同视角分别采集；不能用一张地面平面的映射覆盖不同高度的座位区。
- **座位画面映射：** 当前视角每个可辨认座位的 seat_id、参考点或像素区域及可见范围，和场馆座位表对齐；遮挡或不能区分的座位标明。
- **人员接续样本：** 前段摄像头到鹰眼的同人确认依据、鹰眼内局部 track_id 与匿名 target_id 的核对关系、连续帧及时间。仅时间接近不能证明是同一人。
- **落座参考样本：** target_id、实际 seat_id、开始落座/可确认落座时间、连续视频或帧证据，以及离座／换座例子；区分经过、站立、短暂停留和落座。保留人工确认或候选/未知状态。

判定实际落座需要连续定位与行为证据；单张脸图、靠近某座位、指定座位或相机安装位置都不能单独确定人员最后坐在哪里。

## 按姓名、业务编号或人脸图查询的资料

先用匿名样例提供 `person_entity_id → target_id` 映射、可用查询字段及多候选时如何确认目标。照片检索需要查询照片、已核对候选及与底库一致的特征空间契约：识别/检测模型哈希、检测配置、对齐、预处理与输出版本。可先复用现有特征提取和 `/v1/search`，图片查询不应制造相机观测。首次时间轨迹验收不需要真实姓名和身份证号码。

## 打包和缺失项

建议目录：`cameras.csv`、`sightings.csv`、`clock_checks.csv`、`connections.csv`、`reference_routes.csv`，以及 `images/`、`videos/`、`evidence/`；后续增加 `model/`、`navigation/`、`seats/`、`hawkeye_calibration/`。资料附采集日期、覆盖相机/时间段、版本和字段单位，图片/视频引用使用包内相对路径。

第一趟至少带回：**相机对应表、同一人的跨相机原始观测和录像、时钟证据、现场可通行连接图、人工参考路线。** 缺项写清“未取得／无法确认”及原因即可；不要估填或用现有算法结果填充真值。这样可以判断时间轨迹能验收到哪一步，再安排后续标定。
