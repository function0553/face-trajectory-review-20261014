# 摄像头点位与通道的前向候选

`PredictReachable(snapshot, options)` 根据已经接受的同人经过记录，输出在查询时刻可能到达的摄像头点位、可能仍处于的通道。复用现有抓拍和同人关联；不读取图像，不做人脸推理，不输出详细脚步线或精确位置。

## 输入与证据边界

`options` 必须有整数 `as_of_unix_ms`、`at_unix_ms`，后者不得小于前者。使用明确的轨迹 `version` 可冻结输入。`as_of_unix_ms` 是**名义抓拍时间截止点**；现有记录没有摄取时间历史，因此不能声称还原当时后台已收到哪些消息。函数只读取合格且名义抓拍时间不晚于截止点的 evidence，不读取已经重建的路径、未来抓拍或仿真真值。

接受条件与轨迹入口一致：当前 target、`CONFIRMED`、已有 attribution evidence ID、来源 ID、`UTC_CAPTURE`、`clock_domain=UTC`，时间误差在轨迹策略范围内，且记录不在拒收列表。

相机与通道图使用既有 `CameraGraph`，每条边必须有稳定且唯一的 `edge_id`。图与测试行人的路线无关；`min_travel_ms` 是该连接的最短通行时间，开放时段约束**出发时间**。模型候选图的 `topology_verified` 和 `topology_is_complete` 必须保持 false，只有有证据支持的图才可提高状态。服务入口从已注册图读取这两个标记，调用者不能用单次预测请求覆盖它们。

## 计算方法

1. 用每次抓拍的误差构造闭时间区间。所有区间下界的最大值记为 L。上界不小于 L 的记录都有可能是最后一次观测，保留所有这些相机为起点；各起点最早从 L 开始。这样不会按照误差内不确定的先后顺序擅自选择一台相机。
2. 如果查询时间仍落在最后抓拍的时间误差区间内，返回 `UNKNOWN / CAPTURE_TIME_OVERLAPS_QUERY`。此时可能尚未经过最后相机，前向候选不能覆盖此前位置。
3. 从这些起点执行多起点最早到达搜索。到达相机后允许等待，再根据出发窗口和最短通行时间扩展所有能在查询时刻到达的点位。保留岔路和并行通道，不选定一条行走路线。
4. 默认 `allow_edge_wait=true`，允许人在通道内停留。只要该通道曾可进入，就保留为当前候选；出发窗口关闭不代表把已进入的人移走。显式设为 false 时，才用 `max_travel_ms` 限制通道占用时间。这是假设，不是从抓拍推断到的停留事实。
5. 新观测形成新轨迹版本后，以新的可能最后观测重新求候选，因此起点和分支会变化。旧版本保留原来的候选依据；调用方可比较新观测是否在旧候选中。

以上是保守可达集合，不是完整的历史路径一致性求解：较早观测参与时间排序，但不会用它们强行消除最后时间区间重叠的相机。已有历史轨迹模块继续负责前后观测之间的时空一致性。一个候选点表示“可能已到达并停留”；一个候选边表示“可能仍处于该通道”，都不能宣称已被摄像头再次看到。

## 输出与限制

- `candidate_cameras`：`camera_id` 和 `earliest_arrival_unix_ms`。
- `candidate_edges`：边 ID、方向、可以导致当前通道占用的出发时间范围。
- `latest_observation_candidates`、`based_on_observation_ids`、轨迹版本与图版本：结果依据。
- `CANDIDATE`：在声明的已验证完整图和等待假设下的候选，仍无精确位置或校准概率。
- `CONDITIONAL_CANDIDATE`：图未验证、不完整，或起点未出现在图中。不能依据候选集合之外判定人不在某处。
- `UNKNOWN`：没有合格记录、误差覆盖查询时间、或最后记录已超出预测时限。
- `TRUNCATED`：资源上限触发；已有候选是部分结果，不能用于排除其余区域。
- `search_complete` 仅表示已完成所给图的搜索；`coverage_complete` 还要求图完整、已验证、起点在图中。

默认 `max_horizon_ms=300000`，最多 86400000；时限从最后观测最早可能时间计算，不能用推迟 `as_of` 将陈旧观测变新。默认 `max_expansions=10000`、`max_candidates=10000`（点与边合计）、`max_graph_edges=100000`、`max_evidence=100000`。所有时刻使用 int64，超范围或小数拒收，传播加法避免溢出。

## 本地验证与经验

`evidence/2026-10-07-point-trajectory/reachability_tests.py` 将固定随机种子生成的 48 个微型有向图，分别在 13 个查询时间、2 种通道停留规则下，与独立的整数时间状态穷举器比较，共 1248 个案例。穷举器枚举所有出发时刻、移动时长、等待和零耗时环；不调用最短路算法，也不读取算法输出构造预期答案。相机 ID 仅用于满足绑定协议，测试连边、身份与时间均明确标为合成数据，不是实际场馆连通证明。

额外检查未来记录隔离、误差下的多个最后相机、新记录缩小候选、陈旧记录、未关联记录、资源截断及 int64 边界。测试结果记录 worker 和测试脚本 SHA-256。通过这些检查只能证明本地算法契约，不能替代真实人员连续抓拍、完整通道关系与现场时间标定验收。

容易出错的地方：把相机坐标当成人的脚点；把最短路当作唯一真实路线；用测试路线建立待测图；把最长移动时间当成“绝不可能停留”；让未来抓拍参与旧预测；用名义时间强行排序重叠误差；把搜索完整等同于现场拓扑完整。本实现分别通过点位/通道语义、全部候选、独立通用图、显式等待假设、证据截止点、区间起点与独立完整性标记处理。
