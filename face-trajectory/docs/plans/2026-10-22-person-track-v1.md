# 人员轨迹 v1.0 改造计划

依据用户提供的《人员轨迹三方接口对接协议_v1.0.md》（2026-10-21），本次完成算法侧改造，保留现有查询用于核对。

采用活动 output_mode=PERSON_TRACK_EVENTS，复用现有无空间拓扑的人脸准入及事务 SQLite outbox。旧活动模式保持原合同。只向平台发送已登记 PRIORITY 人员的已确认单脸记录；名单登记必须已有有效模板。内部 outbox 保留上下文，HTTP 正文仅包含协议规定的十二个字段。

同一活动、来源、单脸抓拍保存当前投递修订，初始 UPSERT=1；独立证据纠正后递增并发送完整 UPSERT，撤回发送 RETRACT/person_id=null。元数据从原始抓拍取出，纠正不改采集时间和照片。事件与识别状态同事务提交，容量不足整笔回滚。未交付的新合同消息不受168小时查询清理影响，不改写请求体，成功确认后删除队列。

HTTP 必须同时为200、正文code=200和匹配event_id才确认。其他结果保持原事件，按1/2/5/10/30秒退避，之后30秒；4xx保留并告警，恢复配置后继续原样投递。10秒总超时，禁止自动重定向凭证。

检查重点：同毫秒不同ID不能覆盖；未知姓名/照片字段必须null；修订不能跨重启回退；不把匿名或待确认身份发出；清理不能修改待投递原文。平台TDengine和驾驶舱开发不在本仓库范围，真实联调需对方地址、凭证和图片存储。
