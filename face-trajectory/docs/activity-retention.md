# 活动隔离与168小时滚动保留：统一设计（2026-10-10）

本文件记录编写各阶段代码前的统一设计，以及最后核对后收紧的保留规则。只有带验证证据的项目才是实现完成；当前可执行接入、启动和迁移以[0.13服务合同](activity-service.md)为准，实测见两个项目现有HANDOFF。生产、Java、生产数据库及摄像头只读。本轮所有写入、迁移、清理验证使用新建隔离本地库。

## 作用域与生命周期

activity_id为security_activity.id，activity_num为权威唯一业务编号，venue_id为场地。三者由后端活动同步合同提供，禁止按场地、计划时间、最新活动猜归属。活动创建默认为停止；配置同步、用户选择、明确监控启停三个操作独立。活动配置、绑定、启停分别用CAS版本。配置或绑定变更使旧上下文事件隔离，停止后的迟到事件隔离，不改变其它活动。计划结束时间仅资料，不自动关闭监控。

同一个SQLite权威事务内，State活动视图将关联、监控、人员分类、匿名图库、会话、轨迹版本及其缓存按activity_id隔离，业务person_id保持原值。登记图库与活动状态分开：首版采用每活动登记图库，登记模板不随轨迹到期删除；图库跨活动共享不是默认隐式行为，若后端需要共享，须显式将权威登记模板同步到每个有权活动。匿名模板及来自抓拍的模板更新属于轨迹衍生历史，按期限清理。

设备绑定是明确活动启用范围和route_rule_id/binding_version，不是场地设备列表。共享摄像头输入必须指定权威活动和匹配版本；缺失、冲突或不明确绑定隔离，不能无条件复制。闸机人脸关联必须携带source_id+observation_id及同次通行evidence_id；验票activity_num必须与映射一致，不能认定身份。

## 持久化、幂等、恢复

事件作用域(activity_id,source_id,event_id)，内部采用结构化复合键，不拼接人员ID。同键同内容安全重试；同键异内容409，包括reconsider、时间、绑定、版本或route改变。当前公开接口没有原键补证修订操作；将来需独立有版本合同并保留首次隔离期限，不能把新ID当作延长原事件期限的办法。活动scope覆盖底层关联和状态，恢复时按scope构造独立热索引。旧全局状态不猜活动，保持未归属，全部轨迹内容仍适用清理规则。

客户端身份由可信后端签名授权上下文验证，含subject/session/context_id/context_generation/authz_revision/显式activity动作授权/有限有效期。查询、订阅、配置、监控启停均验证动作；前端自报activity_id不构成授权。查询、推送带activity_id/activity_num/config_version/binding_version/monitoring_version及客户端context/subscription版本。用户关闭订阅、退出或切换不停止后台监控。公平调度按活动轮转；重点优先必须保留普通配额，身份确认门槛一致。

## 时间与保留的共同设计

既有ClockAdapter不可变DEVICE_CAPTURE profile、核验来源、有效校准和CAMERA_CAPTURE_60S继续使用。它保持时区明确的摄像头名义采集UTC，abs(offset)+测量/漂移/量化误差不得超过60000ms，未知/未经核验/超限HOLD。准入后误差重叠保留顺序歧义。

可信当前UTC必须由受信后端或运维签名的有限期参考证明建立，并核验来源、有效期、误差及本地时钟跳变；system_clock可读、NTP开启、历史快照均不构成运行证明。冷启动先发每进程新随机challenge，签名证明必须绑定当前challenge并在短挑战有效期内返回；接收后按单调时钟推进UTC，续期再用新challenge。禁止依赖不可信墙钟判断旧签名是否新鲜。可信端必须将UTC溯源到核验参考（同步状态、来源和误差），不是把机器时间签名即视为核验。测试使用明确标注的合成参考。证明失效时拒绝依赖时间的操作，不凭未知时间删除或给新隔离载荷无限延期。可信UTC水位不可回退。

cutoff=可信now-604800000ms；名义采集时间==cutoff保留，<cutoff过期；不以接收、重试、活动停止、用户切换或恢复时间计时。无可信采集时间从首次可信接收入隔离时起最多168小时，重接收或恢复不重置。期限在存活intake固定，到期墓碑只保留不可逆键/内容摘要，删除原时刻/相机/载荷，防止清理后未知时间输入重新开始期限。

## 清理全部存储位置

P2：observation及历史、monitoring_observation及revision、monitoring_gate及revision、所有trajectory历史版本与head、refs-v1/v2 object树、association派生frame/track/target索引、owned_template与抓拍匿名模板、monitoring_projection缓存、push_outbox载荷及重放来源。窗口内版本必须修剪超窗证据与可恢复该证据的visit/anchor/segment，再按仍存在根引用做共享对象标记清扫。热缓存、重启加载与队列取件统一使用当前期限。

P1：monitoring_delivery库captures的图像/metadata/result、deliveries的payload/receipt/error；旧trajectory_bridge库frames/outbox。Python仅做活动字段传递及兼容，不实现新的清理生产模块；C++/Go清理适配器覆盖这些库。P1旧缺活动来源隔离，不继续发送到默认活动。

旧全局/未归属/待决数据有可信时间按采集时间清理。缺可信首次隔离依据的旧数据和P1未知时间数据采用立即到期，不在迁移时给新168小时窗口；新P2未知事件由可信接收入隔离时固定首次期限。登记模板、活动主表、必要配置/绑定/监控生命周期、后端验票历史及录像排除。最小运行状态不可含超窗位置、时间序列、旧事件载荷；继续监控所需状态与轨迹历史分别处理。

清理以可恢复SQLite事务为批次，dry_run只读统计不改变水位/索引/数据；真实清理提交后重建热索引，再secure_delete、VACUUM与截断WAL/空闲页。P1外部清理请求驱动匹配消费者暂停、排空进行中的推理与发送、清空热缓存/原生reader、关闭连接及释放租约，维护成功再重开并恢复；失败保持待维护，下一轮续做。报告不可查询/不可重放、有效数据量、可复用空间、文件体积、多轮轨迹增长约束和墓碑增长，不能仅以文件变小或宣称总文件恒定为依据。持续清理默认只统计，明确启动retention-enabled才删除；需有计数、耗时、最近成功/失败、时钟状态；中断事务回滚，下次重跑安全。
